Tuning DINOv3 for the whole-image check (Path A), 31 Oct 2026. Experiments in order of size (smallest change
first), same start (original DINOv3 + head F), same validation. python -m src.models.tune_backbone (the first run
used its predecessor src/models/tune_layernorm.py, same method).

Why: frozen DINOv3 + linear head can't tell Muse Image edits from their real originals (results/muse_edits_v1.txt):
  edits-only linear probe AUC 0.73-0.75 (app view), 0.70-0.745 with 448 px crops at full resolution (no shrinking),
  strongest-spot pooling of patch scores 0.55-0.57 on local edits; frozen heads G1/G2 trained with the edits
  (weights/muse_edits_v1) gain a little on whole-image edits but lose 3-24 points elsewhere -> head F stays.

Training data (12,648 pictures; each class counts half): SID-Set files 10-14 (1,375 real / 1,443 FLUX), Commons
train (1,659 real), Muse pairs v1 (320/320) and v2 (387/387), SD 1.5/2.1 faces (1,200 AI), SD 3.5 + Kandinsky
(1,073 AI), Muse training edits of people-free Commons (1,107) and OpenImages (1,135) photos, each with its original
(real). Random training view as for the frozen heads; batch 16; AdamW; L2 pull to the original weights 1e-3.
Validation: dev sets only, at most 200 per set; the line = at most 5% of every real pool (polished dev, OpenImages
val, edit originals = the 38 people-free dev photos behind the 76 Muse test edits, counted twice).

Why the strict line hurts (short448 medians, head F -> step 2000): polished dev -3.73 -> -2.83, edit originals
-3.72 -> -0.91, local edits -3.51 -> -0.21, whole edits -1.52 -> +1.73. The tuned model raises the edits, but also
their REAL originals almost as much, and the originals (people-free scenes) set the line. Same 38 photos as camera
files vs. the 1536-px copies sent to Muse: copy - camera median +0.02 for both heads, so not file processing.
Reading: the model can't yet separate an edit from its original, so for these pairs the cheapest loss is ~50% for
both; that raises every photo that looks like an edit source (people-free scenes). A real false-alarm risk for real
landscape / object photos (priority #1). LayerNorm-tuning alone: AUC 0.61 -> 0.76, not near-perfect.

More capacity helps the edits (AUC 0.76 -> 0.85, whole edits up to 72%) but Muse text-to-image stays below head F at

== Decision ==
A frozen probe on the middle layers (results/backbone_probe_v1.txt) separates edits from their own originals far
better: PE-Core-L all layers AUC 0.972 on 198 new held-out edits (DINOv3 last layer 0.745). So the tuning runs stop
here; head F stays the whole-image check (unchanged, with its phone calibration), and a separate Muse-edit check on
frozen PE-Core is built next (src/models/train_edit_check.py). Full fine-tuning was not run: the cheaper frozen route
already beats the tuned ones on the hardest test.
