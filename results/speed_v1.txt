Speed of the full app pipeline per photo (1 Nov 2026): DINOv3 whole image + PE edit check + SAM 3 faces + each face
through DINOv3 + metadata; without the optional Meta API investigator. The four app samples (app/examples), laptop
(i7-14HX, RTX 5050 8 GB); the same verdicts on GPU and CPU.

  device                     per photo      model load (local cache)
  GPU, bf16                  0.6-0.8 s      (first photo 2.3 s)
  CPU fp32, 8 threads        16-20 s        10 s
  CPU fp32, 2 threads        33-38 s

SAM 3 (1008 px) takes most of the CPU time (10.7 s of it on 8 threads, measured 29 Oct). Hugging Face Space CPUs are
usually slower than this laptop's cores: expect roughly 25-35 s on "CPU Upgrade" (8 vCPU) and about a minute on the
free tier (2 vCPU). Fine-tuned PE weights are loaded directly (the original PE weights are no longer downloaded).

== Hosted demo on Google Cloud (3 Nov 2026), measured from India over the internet (upload + check + answer) ==
Same app (app/server.py), CPU only (no GPUs on the free trial). The four public sample photos (app/examples):
  e2-standard-8 (8 vCPU), fp32:                       34-53 s per photo
  c3-standard-8 (8 vCPU, Intel with AMX), fp32:       19-29 s (first request after a start 37 s)
  c3-standard-8, bf16 (AMX; src/models/backbone.pick_dtype since 52f348d): 7-11 s
On the c3 machine alone: SAM 3 face finding (9-face photo) 16.3 s fp32 -> 5.8 s bf16 (same 9 faces, boxes within
~4 px); DINOv3 whole image 1.0 s -> 0.3 s; 8 threads instead of 4 gain only ~6%.
The 80 judge-test AI pictures through the hosted app (c3, bf16): same verdict as the laptop (GPU, bf16) for 80 of 80,
largest AI-evidence difference 0.026; median 9.1 s per picture, slowest 32 s.
Investigator step on the hosted app (Muse Spark names the changed object, SAM 3.1 outlines it, Muse Spark explains):
red-bicycle sample -> "red bicycle", outlined, explanation written; 18.6 s, < $0.01 of Meta API credit.
